# SOP SLOP v0.7 evaluation — 2026-09-06

## Conclusion

The v0.7 candidate is suitable for backed-up local activation. It preserves the
successful behavior of one controlled build trial while adding command-observed,
durable closure and tested rejection of unsafe/inconsistent supervisor operations.
It is **not yet evidence of generally better intent understanding, faster delivery,
fewer questions on ambiguous work, or production reliability across real projects**.

## Deterministic failure/integration tests

29 tests in `tests/test_supervisor.py` passed. These measure supervisor behavior,
**not** a 29-case old/new model benchmark:

- Complete red/green/seal/cleanup/review/restart and local integrity.
- Empty answers, delegated security choices, three-question ceiling and routine
  auto-decisions without spending question budget.
- Lost annotations, incomplete acceptance coverage and malformed input rollback.
- Pending-input execution gate, side-quest mission preservation and durable dedup.
- Uncertain dispatch retry rejection and cross-worktree writer collision.
- Claimed passes without observations, failed checks, changed candidate content,
  changed assertions and legitimate replan generations.
- Timeout, bounded output, redaction, mutation during a check and a killed
  supervisor leaving a live child process group.
- Required/optional independent review, fatal/revision-required blocking, and
  repeated-freeze rejection bypass prevention.
- Release authority, contract/target-bound extra authority, exact revision/target
  observation, clean committed release candidate and upstream graph/skill drift.
- Immutable delivery, durable successors, resource preservation, and effective
  failure downgrade without rewriting the original delivery receipt.

Release observations here use explicit synthetic fixtures. No production provider,
credentials, deployment or canary was exercised by this package test suite.

During implementation, executable tests/independent review found and fixed:

1. A valid test replan still compared against old assertion hashes.
2. Optional fatal review could be ignored, then a repeated freeze could erase it.
3. Crashed/interrupted supervisor could leave its real child running.
4. Repeated legitimate argument flags were rejected.
5. Additional release authority survived a changed target.
6. Structured provider JSON retained arbitrary unredacted diagnostic fields.
7. Output was memory-bounded but not disk-bounded; capture now drains bounded pipes.

Independent reviewer accepted the final exercised implementation, additionally
proving review-only closure without writer lease, changed-target authorization
rejection, fresh target authority success, and secret-safe structured receipts.
The final narrow nested-input validation addition and saved-product replay were
verified by the coordinator after that review; they were not represented as
having received a second independent implementation review.

## Compatibility and size

The existing v0.6 graph, forward replays and installer tests still pass:
41 nodes / 102 edges, 66 negative graph cases, 5 cleanup/deliberation negatives,
23 additional deliberation negatives and both zero-diagnostic forward fixtures.
Those are legacy structural diagnostics, not the active controller.

The active entrypoint fell from 4,143 to 1,318 whitespace-delimited words
(about 68% shorter). The six phases do not imply only six reasoning decisions;
specialist techniques remain conditional. Runtime enforcement adds a Python
standard-library module and SQLite state; no third-party runtime dependency,
daemon, model-specific agent configuration or upstream fork was introduced.

## Remaining evidence limits

One paired, clear T1 build cannot establish broad superiority. Both versions asked
zero questions, so a claim that v0.7 already reduces real-world grilling would be
unsupported. Ambiguous intent, duplicate observation batches, mid-run additions,
long-context restart, T2/T3 architecture, real browser QA, provider failures and
multi-project rollout need further live trials. The deterministic tests prove
specific mechanics, not that every agent will call those mechanics correctly.

The supervisor cannot intercept arbitrary host tools, authenticate controller
claims, judge test adequacy by itself, or prevent false chat finals. Review/user
attestations remain labelled. Secrets are best-effort redacted, not magically
safe to print. Side-quest dispatch requires explicit host/user authority and is
not an automatic background service. Policy learning remains proposal-only.

## Local promotion and rollback

Activation is local, after package checks, independent review and paired trial.
Keep the previous installed package in a timestamped backup outside skill
discovery. Read back installed files and rerun package validation. Preserve the
source branch, synthetic evaluation artifacts and existing uncommitted handovers.
Do not publish the research or raw transcripts. Public GitHub upload was not
resumed by this implementation request.

Rollback restores the previous package from that backup; retain each repository's
local `.git/sop-slop` state as historical evidence. The older skill cannot resume
v0.7 supervisor runs; finish/reconcile them using their pinned package first.
