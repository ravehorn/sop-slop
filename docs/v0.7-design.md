## Outcome

Turn an idea or annotation batch into an explicit behavior contract, bounded work,
observed checks, and a truthful completion report. Ask only the questions whose
answers change that contract. Resume without reconstructing the entire conversation.

## Decision

Use a Python-standard-library local supervisor with SQLite transactions. Six
phases replace the mandatory 41-node execution itinerary: understand, plan, build,
check, release, finish. Conditional upstream techniques still supply domain,
product, design and engineering judgment. The v0.6 graph and its validators remain
available as historical diagnostics, not a second active controller.

The native supervisor records the mission, acceptance examples, source-to-problem
mapping, scoped authority, decisions, pending work, command observations, review,
candidate identity, release observations, cleanup dispositions and final review.
Product documents and the existing task tracker retain their authority; the local
database stores execution state and references, not another product backlog.

Alignment begins with a brief derived from the request and repository: intended
outcome, concrete before/after examples, invariants, non-goals and the requested
finish. Explicit requirements can lock directly. In v0.7.1, three answered material
questions trigger a brief check-in, not a ceiling. Continue targeted clarification
for important or ambiguous work until remaining choices can safely be delegated.
Never infer an answer from an empty picker. Delegated
recommendations cover named reversible choices, not destructive actions or
expanded authority.

All linked worktrees share one writer lease via their Git common directory.
Unknown or abandoned ownership requires explicit recovery, never a timer-based
lease steal. Native checks run a fixed argument vector, capture their actual exit,
bound output and runtime, and bind evidence to the working-tree content and the
approved check definition. Reviewer claims cannot replace test observations.
Failed checks remain visible; changed code invalidates candidate proof.

Side quests are captured before dispatch. A stable work-item key prevents repeat
capture. Starting a separate Codex task depends on explicit user/host authority.
An uncertain spawn remains pending reconciliation; do not blindly retry.
Completed delivery is sealed; later substantial work receives a successor item.

Use installed upstream skills as techniques with their actual file digests
recorded at intake/use. Do not update them during a run. Host instructions and the
user's existing authorization govern release. If an upstream compound executor
cannot honor that scope, use the repository's documented release commands and
capture their observations; a prompt does not sandbox an executor.

## Enforcement limits

This is an in-task supervisor, not an always-running service, security sandbox,
unforgeable attestation service or host hook. It can reject invalid operations
through its CLI, but cannot intercept arbitrary Codex tools or prevent dishonest
chat finals. The host sandbox and external branch/deployment protections remain
the actual permission boundaries. Stored human/host observations are attributed
as such; never relabel controller testimony as independently observed truth.
No paused company/memory services, dashboard, model pinning or distributed queue.

## Implementation and proof

1. Preserve baseline, define the six-phase contract and build transactional CLI.
2. Add bounded alignment, durable work queue, repository writer lease, observed
   checks, stale-evidence rejection, sealed completion and cleanup/review.
3. Rewrite the skill entrypoint and adapters around those commands. Keep upstream
   installations untouched; retain legacy replay validation for comparison.
4. Test restart, failure/timeout, red-to-green proof, definition tampering,
   stale candidates, incomplete acceptance, lease collisions, unknown spawns,
   delegated decisions, authority and target preservation, closure and learning.
5. Compare old and new on identical probes; run independent live-agent trials on
   disposable products. Report observed behavior separately from enforcement
   coverage. One trial is not evidence of a population-wide success rate.
6. Activate the verified local skill with a recoverable backup outside discovery.

The completion target for this implementation is an installed, locally verified
skill with a reproducible comparison report. Public release of this research
material was previously stopped; it is not silently resumed by this build.

## Verification result

See [the evaluation report](v0.7-evaluation.md): 29 integration/failure tests,
preserved legacy validation, independent review, and one paired live build with
eight independently checked acceptance behaviors per version. Both versions
produced correct products with zero questions; only v0.7 demonstrated native
durable closure. This does not establish population-wide speed or alignment gains.
